## Product decisions (binding, controller rulings R15–R24)

- **R15 Never lose work silently (C1).** `Library` gains optional `exportedAt?: string` (ISO, set by applyExport; absent = never exported). A painting is _unexported_ when the library was never exported, or it is unpublished, or its `updatedAt` is after `exportedAt`. Closing or replacing a library (Close library, Start a new library, Try the sample library) shows a dialog naming how many unexported paintings would be deleted; primary action "Export first" (goes to Export), secondary danger action "Delete {n} and close". When nothing would be lost, a simple confirm. Copy must be truthful (no "stays safe" unless true).
- **R16 Status vocabulary (I1, I26).** New paintings start `ready`. Details shows a switch "Include in the next export" (on = ready, off = draft). Badges: Draft · Ready · Changed (published and updatedAt > exportedAt) · Published. Library filter chips: All · Ready · Draft · Published. Library export button: "Export · {n} ready" (+ " · {m} changed" when relevant), primary only when n + m > 0, secondary otherwise (N1). Export pre-ticks every ready painting that has a picture.
- **R17 IDs follow the title until published (I2).** While unpublished, `id = slugify(title) + '_' + existingSuffix` is recomputed when the title changes (unique within library + loose; regenerate suffix on collision). Published IDs never change. Details shows "Will be `…`" (unpublished) or "`…` · never changes" (published).
- **R18 No blank paintings (I3).** "Create a painting" opens the editor on an unsaved draft that only enters the workspace on the first change.
- **R19 Editor autosaves (I11).** Edits are committed to the workspace automatically (debounced ~800 ms and on leave); the top bar shows "Saving…" / "Saved". The Save button and the unsaved-changes dialog go away; Ctrl+S flushes immediately. Undo/redo still work within the session.
- **R20 Auto-size on first picture (I4).** When a painting gets its first picture and was never resized, pick W×H in 1..4 blocks minimising the aspect-ratio error (tie → larger area), toast "Sized to W×H blocks to fit your picture" with "Change" (goes to Size & crop).
- **R21 Import from any library (I13).** Same namespace → merge (current rules). Different namespace → its paintings are added to the open library as new unpublished copies (fresh IDs, status ready), with a confirm naming the source library and the count. With no library open, opening a pack opens it (current behaviour).
- **R22 Namespace is an advanced detail (I14).** The New library dialog asks only for a name; "Pack ID" (namespace) sits under an "Advanced" disclosure, auto-derived, explained ("Used by the server. It can't change after the first export.").
- **R23 Demo library (M12).** The sample library is a demo: titles localised, a banner says it's a demo, and Export is disabled with "Create your own library to export". Its namespace stays `sample`; mark it with a workspace-only flag (not written to packs).
- **R24 Performance budget (C2, C3, I18, N5).** Render in a Web Worker (latest request wins, stale results dropped); memoise pipeline stages so glass/frame/shape changes skip resample/quantize; during slider drags and strokes show a fast path (strokes composite onto the last rendered raster without re-running the pipeline; full render on release). Target: input→paint under 50 ms at 16×16 @ 64 ppb for glass/frame/shape and strokes, under 120 ms for picture adjustments with the Minecraft look. Export builds in a worker with progress "Rendering {i}/{n}…".
